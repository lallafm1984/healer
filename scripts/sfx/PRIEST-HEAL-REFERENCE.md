# 참고 음원 기반 사제 치유음 — 2026-10-21

사용자가 제공한 `coghezzi-holy-healing-spell-533279.mp3`를 로컬에서 분석하고,
설치된 Agent Audio의 Stable Audio 3 Medium으로 audio-to-audio 변주를 만들었다.
원본 파일은 수정하거나 업로드하지 않았다. 유료 API 호출은 없다.

- 청음: `http://127.0.0.1:5173/scripts/sfx/audio-comparison/priest-heal-20261021/index.html`

- `heal-priest-holy.wav` / `.ogg`: 화음 변화가 더 있는 사제 치유 변주
- 두 파일 모두 2.60초, 44.1kHz, 스테레오. 현재 게임 음원은 유지했다.
- 생성 프롬프트·시드·처리·해시·판정 기록: 결과 폴더의 `review.json`

## 원본에서 확인한 특징

원본은 2.534초, 44.1kHz 스테레오다. 약 0.84~0.87초에 가장 크게 부풀고,
대부분의 에너지가 1.32~1.34초 안에 소진된 뒤 잔향이 사라진다. 시간 범위는
모노 합산과 스테레오 에너지 분석 방식에 따른 차이다. 스펙트럼 중심은 약
774Hz이며, 모노 합산 에너지의 약 80%가 250~1000Hz에 모여 있다.

로컬 CLAP 설명 비교에서는 공기감 있는 상승음과 합창 같은 합성 화음이
하프·물방울·단독 벨 소리보다 잘 맞았다. 따라서 짧은 타격음 대신 부풀어
오르는 화음과 자연스러운 감쇠를 프롬프트에 반영했다. 이는 신호와 모델의
분석이며 직접 청음으로 악기나 연주법을 확인했다는 뜻은 아니다.

## 생성·재검수

총 8개를 생성했다. 변형 강도 0.50/0.65, 0.40/0.40, 0.15/0.25,
0.03/0.10을 차례로 비교했다. 마지막 두 개는 각각 1/2스텝이고 나머지는
8스텝이다. 기본 런타임과 가중치 설정은 수정하지 않았다.

원시 출력은 모두 사전에 설정한 CLAP 음색 유사도 기준 0.65 미만이었다.
낮은 변형 강도에서도 원본의 에너지 흐름은 보존되지만 조용한 끝부분에
코덱 잡음이 남는 것을 확인했다. 변형 강도 0.25와 0.03의 두 출력에
스테레오 연동 익스팬더(-72~-58dBFS), 끝 80ms 페이드, RMS -24dBFS 음량
조정을 적용했다. 원본 샘플을 새 결과에 섞지 않았다. 비교용 원본도 같은
평균 음량으로 맞췄으며 원본 MP3에는 손대지 않았다.

최종 결과는 같은 기준으로 다시 검사했다.

CLAP 값은 확률이나 청취 유사도 백분율이 아니다. 무음·클리핑·지나친 고음·
잘린 잔향과 음성/음악/잡음 설명 우세 여부도 확인했다. **직접 청음 평가는
수행하지 않았다.** 결과는 사용자가 비교할 수 있는 후보이며 게임 적용에
대한 청취 승인을 의미하지 않는다.

## 재현

`generate-reference.py`는 Agent Audio 패키지 가상환경에서 실행한다.
설치 상태와 고정된 업스트림 리비전을 확인하고 공유 생성 잠금을 사용한다.
공식 로컬 CLI의 `--init-audio`를 사용하며, MCP의 텍스트 생성 인터페이스에
없는 매개변수를 추가한 것이 아니다. 모델을 다운로드하지 않는다.

- 런타임: `779434a908193105335fd8d833418603625b2859`
- 모델: `da6edc54ddba10bfd79a077102ded687f80e882b`
- Medium DiT fp32, SAME-L encoder/decoder w8a8, TFLite CPU
- 원본/중간 파일: `.sfx-raw/priest-reference-20261021/` (Git 제외)
- `generate-reference.py --home <agent-audio-home> --manifest <manifest.json>`
- `prepare-reference.py <source.wav> <finished.wav>`
- `review-reference.py <reference.wav> <candidates...> --model <local-CLAP> --report <screening.json>`
- `publish-reference.py <work> <new-output-folder> --original <original.mp3>`

전처리·검수는 numpy/scipy/torch/transformers가 있는 분석 환경에서,
발행은 soundfile이 있는 Stable Audio 런타임 환경에서 실행한다. 기존 생성
파일을 덮어쓰지 않으며 새 이름이나 출력 폴더를 사용해야 한다. 원본 참고
음원은 Git이나 배포 폴더에 복사하지 않고 개발 서버의 작업 파일로 재생한다.
