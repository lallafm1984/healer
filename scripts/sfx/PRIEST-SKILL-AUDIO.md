## 사용자 확정 · 2026-10-21

사용자가 최종 수정본을 머지하고 Claude에게도 사제 효과음을 정했음을 알리도록 요청했다.
현재 아래 17종이 확정본이다. [priest-approved.json](priest-approved.json)에 파일별 SHA-256과
실제 디코딩 길이를 기록했다. 사용자의 추가 수정 요청 전에는 재생성·교체·재조정하지 않는다.
이는 사용자의 확정 요청을 기록한 것이며, 제작 기록의 자동 신호 검사를 직접 청음 평가로 바꾸어 쓰지 않는다.

시전 시작음과 시전 루프는 사용하지 않는다. 모든 효과음의 상한은 1.5초다.
순간 치유는 치유 원음 100%를 음정 변화 없이 0.50초로 압축한 버전,
수호 영혼은 0.75초, 생명 구출은 1.45초, 쉼터는 첫 울림과 고음을 부드럽게 한 약 0.525초 버전이다.
소생은 짧고 명쾌한 버전, 천상의 찬가·기적의 순간·흩날리는 빛은 맑은 버전,
치명적 치유는 높인 음량을 유지한다. 천상의 찬가 회복 틱은 반복 재생하지 않는다.

## 최신 수정: 쉼터의 타격감 완화

기존 Agent Audio 쉼터 음원의 음정과 길이(약 0.525초)를 유지하며 첫 울림을 부드럽게 편집했다.
80ms smoothstep 어택과 2.4kHz 위로 점진적으로 약해지는 최대 -4dB 고음 셸프를 적용했다.
평균 음량은 약 -27.5dBFS, OGG 재디코딩 후 전체 피크는 약 -10.9dBFS다.
처음 25ms의 피크는 약 13dB 낮아져 시작 타격음이 덜 튀도록 했다.
25ms 끝부분 감쇠를 적용했고 클리핑·무음·마무리 잘림·중음역 검사를 통과했다.

쉼터 한 파일만 바꿨으며 다른 112개 효과음은 해시가 같다. 새 모델 호출과 유료 API 호출은 없다.
직접 청음 평가는 하지 않았다. 편집 레시피·검수·전체 해시는 `priest-shelter-soft-review.json`,
편집 전 원본은 `.sfx-raw/priest-shelter-20261021-v7`에 보존한다.
효과음 목록 테스트 4개·타입 검사·빌드를 통과했다. 브라우저에서 113개 길이 검사와
쉼터의 실제 특성 발동 이벤트 재생을 확인했으며 콘솔 경고·오류는 없었다.

## 이전 수정: 순간 치유를 치유 원음으로 직접 편집

사용자가 이전 순간 치유에서 치유의 느낌이 나지 않는다고 평가했다.
이전 배합은 새 공기음 비중이 컸다. 이번에는 **치유 원음 100%**로 만들고
새 생성음이나 다른 층을 섞지 않았다. 기존 Agent Audio 제작 `heal-priest.ogg`의
완전한 유효 구간(0.005초부터 0.965초 길이)을 음정 변화 없이 **0.50초**로 압축했다.
원래 시작 40ms를 유지하고, 8ms 교차 전환과 35ms 마무리 감쇠를 적용했다.
파일 RMS는 약 -23dBFS로 정리해 이전 순간 치유보다 약 2.8dB 높였다.

자동 분류 점수를 높이기 위해 다른 음색으로 바꾸지 않고, 사용자가 지정한 원음과
편집 출처를 우선했다. 클리핑·무음·끝부분·중음역·OGG 재디코딩 검사를 통과했다.
직접 청음 평가는 하지 않았다. 치유 원본과 다른 111개 효과음은 해시가 같고,
순간 치유 한 파일만 교체했다. 수호 영혼은 0.75초, 전체 효과음 상한은 1.5초를 유지한다.
새 모델 호출 및 유료 API 호출은 없다. 편집 수치와 검수·해시는
`priest-flash-direct-review.json`, 원본은 `.sfx-raw/priest-flash-20261021-v6`에 보존했다.
효과음 목록 테스트 4개·타입 검사·빌드를 통과했다. 브라우저에서 전체 113개 길이 검사와
순간 치유 완료 이벤트의 `priest-flash` 재생을 확인했으며 콘솔 경고·오류는 없었다.

## 이전 수정: 순간 치유·수호 영혼 더 짧게

순간 치유는 기존 치유의 음정·따뜻한 울림을 참고한 **0.65초** 효과로 바꿨다.
치유 원음을 음정 변화 없이 0.60초로 압축한 참조와 Agent Audio / Stable Audio 3 Medium으로
새로 생성한 빠른 공기음을 섞었다. 생성 후보 3개와 배합 후보 3개를 검사했으며,
최종 배합은 RMS를 맞춘 참조 0.10 / 새 생성음 0.90이다. 기존 기준을 바꾸지 않고
참조 음색 유사도·신호·원치 않는 소리 분류 검사를 통과한 후보만 적용했다.
직접 청음 평가는 하지 않았다. 기존 치유 파일 자체는 그대로다.

수호 영혼 **발동음은 1.45초 → 0.75초**로 줄였다. 원래 어택과 전체 울림을 유지하는
음정 보존 압축을 적용하고, 끝부분 감쇠와 OGG 디코딩을 검사했다.
생명 구출음은 1.45초를 유지한다. 다른 111개 효과음은 변경하지 않았다.
전체 113개 효과음이 계속 최대 1.5초다. 최신 생성·편집·검수·해시는
`priest-flash-guardian-review.json`, 원본과 후보는 `.sfx-raw/priest-flash-20261021-v5`에 있다.
유료 API 호출은 없다.
효과음 목록 테스트 4개와 타입 검사·빌드를 통과했다. 브라우저에서 113개 파일 길이 검사,
순간 치유 완료 및 수호 영혼 발동 이벤트의 전용음 재생을 확인했고 콘솔 경고·오류는 없었다.

## 이전 수정: 맑은 음색·전체 효과음 최대 1.5초

다시 제작했다. 소생은 기존 순간 치유 파일을 참조한 audio-to-audio 변형이며, 다른 네 소리는
맑은 유리·셀레스타 계열을 각각 새로 생성했다. 순간 치유 원본은 변경하지 않았다.

나머지 11개는 전체 흐름을 1.45초로 압축했다. 평온도 음색은 유지하되 최신 길이 제한을 적용했다.
최종 파일 113개가 모두 최대 1.5초이며, 96개 파일은 원본 해시가 같다.
게임 재생기도 속도를 낮춘 경우 마지막 40ms를 감쇠하여 1.5초에 종료한다.
합성 대체음과 재생성 목록에도 같은 상한을 반영했다. 시전 시작음은 계속 사용하지 않는다.

검수·생성 요청·편집 레시피·전체 파일 해시는 `priest-clear-review.json`, 생성 방향은 `priest-clear.json`에 있다.
원본과 탈락 후보는 `.sfx-raw/priest-clear-20261021-v4`에 보존했다.
유료 API 호출과 직접 청음 평가는 없다. 테스트 페이지의 「전체 파일 검사」는 사제 17개뿐 아니라
게임 효과음 113개 전체를 브라우저에서 디코딩하고 길이를 검사한다.
관련 테스트 32개와 타입 검사·배포 빌드를 통과했다. 브라우저에서도 113/113 길이 검사,
사제 17종 실제 엔진 이벤트 순차 재생을 확인했고 콘솔 경고·오류는 없었다.

## 이전 수정: 소생·수호 영혼 생명 구출

사용자의 추가 요청으로 두 음원만 다시 제작했다.
소생은 날카로운 팝 대신 부드럽게 스치는 공기와 은은한 유리 배음을 사용한 0.63초 효과다.
생명 구출은 작은 반짝임에서 상승하는 유리 배음과 따뜻한 셀레스타 화음이 피어나는
2초 효과로 바꿨다. 새 생명이 탄생하는 부드럽고 희망적인 방향이다.

Agent Audio / Stable Audio 3 Medium으로 두 원본을 새로 생성했다.
소생 첫 후보는 잔향 잘림으로 탈락해 완전한 본체를 골라 음높이를 유지하며
0.60초로 압축한 뒤 다시 검수했다. 앞뒤 여유를 포함한 적용 파일은 0.63초다.
생명 구출은 첫 생성본이 통과했다. 두 파일의 신호·CLAP 및 OGG 재디코딩을 검사했고,
나머지 15개 파일은 해시가 같음을 확인했다. 유료 API 호출과 직접 청음 평가는 없다.
최신 생성 요청·편집 레시피·검수·해시는 `priest-renew-rescue-review.json`을 따른다.
원본은 `.sfx-raw/priest-renew-20261021-v3`에 보존한다.
관련 테스트 29개와 타입 검사·배포 빌드를 통과했다. 브라우저에서 17/17 디코딩,
소생 완료 이벤트와 수호 영혼 구출 이벤트의 전용음 재생 및 콘솔 오류 없음을 확인했다.

## 역할별 음색 재제작 이력

사용자 후속 요청에 따라 **모든 직업의 시전 시작음을 제거**했다.
공통 재생 호출, 합성 대체음, 공통 `cast.ogg`와 사제 `priest-cast.ogg`,
목록과 테스트 버튼까지 제거했다. 시전 시간·스킬 동작·완료음은 유지한다.

치유·순간 치유·성언: 평온·정화의 기존 OGG는 해시가 같은 파일 그대로 보존한다.
나머지 13종은 기존 치유 레퍼런스를 쓰지 않고 설치된 Agent Audio / Stable Audio 3 Medium으로
새로 생성·편집했다. 소생은 0.65초의 가벼운 짧은 효과로 적용했다.
새 생성 21회와 편집 후보 3개를 검수했다. 최종 준비음은 새 글로켄슈필 생성본의
음높이를 유지하면서 길이를 줄였고, 전이음은 새 빛방울 생성본을 두 번 배치해
두 번째 음높이와 좌우 균형을 바꿨다. 부모 파일·해시·편집 수치는 보고서에 남긴다.

| 효과음 | 새 소리 방향 |
|---|---|
| 소생 | 짧고 부드러운 생기 한 점 |
| 치유의 기원 | 퍼지는 하프 아르페지오 |
| 수호 영혼 | 날갯짓과 보호막의 금속 공명 |
| 천상의 찬가 | 짧은 파이프 오르간 화음 |
| 빛의 전이 | 서로 다른 높이로 도약하는 두 빛방울 |
| 기적의 순간 | 역방향 심벌과 밝은 셀레스타 |
| 쉼터 | 부드럽게 펼쳐지는 장막과 목재 공명 |
| 기도의 정점 | 상승하는 글리산도와 정점의 울림 |
| 흩날리는 빛 | 잘게 흩어지는 유리 풍경 |
| 평온 준비 | 명확한 상승 두 음 |
| 치명적 치유 | 작은 결정 반짝임 |
| 수호 영혼 생명 구출 | 날개가 받아내는 묵직한 구출 |
| 빛의 전이 이동·소멸 | 가볍게 도약하는 빛방울 |

`priest-redesign.json`은 생성 방향, `priest-redesign-review.json`은 최종 파일 해시,
기존 네 파일의 보존 해시, 후보별 검수와 생성 요청을 기록한다.
실제 길이와 현재 테스트 목록은 `priest-theme.json`을 사용한다.

검수는 실제 치유음과의 CLAP 유사도 ≤ 0.80(소생 제외), 개별 재질·동작 설명과의
유사도 ≥ 0.22, 말소리·노래·배경 음악·잡음의 우세 여부, 자연스러운 종료와
클리핑·휴대폰 중역을 확인한다. 최종 비교 음량은 공통 RMS -24 dBFS로 맞추고,
게임 파일에는 각각의 조용한 믹스 음량을 적용한다. 기존 공통 전투음 검수의
잔향·중역·피크 기준을 사용하며, 자동 점수는 직접 청음을 대신하지 않는다.
두 음이 한 구절인 효과는 250ms 이내의 간격을 같은 효과로 분석한다.
기존 단일 타격음의 80ms 구간 분리 기본값은 유지하며 회귀 테스트를 추가했다.
전이의 최초 실제 구슬 충돌 방향이 부적합해 빛방울 두 음으로 변경한 전후 보고서를
원본 폴더에 구분해 보존했다. 수호 영혼은 자연스러운 끝까지 1.915초를 확보했다.

최종 검증: 관련 TypeScript 테스트 29개와 신호 처리 회귀 테스트 6개 통과,
타입 검사와 배포 빌드 통과. 새 13개 파일은 이전 버전과 다른 해시이며,
유지 요청한 4개는 동일한 해시다. 배포 빌드의 기존 큰 청크 경고는 남아 있다.
실제 브라우저에서 17/17 스테레오 디코딩과 17종 순차 재생이 완료됐고,
시전 시작 버튼 0개 및 콘솔 오류 없음을 확인했다.

재현 순서(저장소 루트에서 실행, 새 작업 폴더 사용):

1. `priest-redesign.json`을 작업 폴더의 `manifest.json`으로 복사한다.
   보존할 네 파일의 이름·SHA256을 `preserved.json`에 저장하고, 실제 `heal-priest.ogg`를
   PCM16 `heal-comparison.wav`로 변환해 작업 폴더에 둔다.
2. Agent Audio Python으로 `generate-combat.py --home E:/claude/.agent-audio --manifest <작업 폴더>/manifest.json --round 1`을 실행한다.
3. 분석 Python으로 `priest-redesign.py review --work <작업 폴더> --model <로컬 CLAP 폴더>`를 실행한다.
4. 보고서의 불합격 이름만 `--names`에 넘기고 새로운 후보 번호로 생성한다.
   재질 지시를 크게 바꿀 경우 `retryPrompt`를 기록하고 `--round 4` 이상을 사용한다.
   준비음의 타이밍 편집과 전이의 두 음 편집은 최종 보고서의 `processing` 레시피를 따른다.
5. 13종 모두 통과하면 런타임 Python으로 `priest-redesign.py publish --work <작업 폴더>`를 실행한다.
   네 파일 보존과 모든 인코딩을 먼저 검증한 후 새 음원을 일괄 적용한다.

아래는 최초 18종 제작의 이력이다. `priest-theme.py`는 최초 보고서의 레시피를 읽는
이전 레퍼런스 파이프라인이며, 현재의 역할별 음색 재제작에는 위 절차를 사용한다.

## 음색과 파일

기준은 이전 치유 비교의 `heal-priest-holy.wav`와 `heal-priest-close.wav`다.
따뜻한 중역 화음, 상승하는 공기 소리, 둥근 시작과 부드러운 잔향을 사용한다.
세부 이름·길이·음량·프롬프트는 `priest-theme.json`, 실제 선정 파일과 해시는
`priest-theme-review.json`에 기록했다. 게임 파일은 `src/sfx/*.ogg`에 있다.

| 범위 | 효과음 |
|---|---|
| 기본 스킬 | 치유, 순간 치유, 소생, 치유의 기원, 정화, 수호 영혼, 천상의 찬가, 성언: 평온, 빛의 전이 |
| 버튼형 특성 | 기적의 순간, 쉼터, 기도의 정점, 흩날리는 빛 |
| 피드백 | 시전 시작, 평온 준비, 치명적 치유, 수호 영혼 생명 구출, 빛의 전이 이동·소멸 |

시전과 전이 이동은 전이의 공기 상승 음색을, 치명타는 평온 준비의 짧은 화음을
작은 음량으로 공유한다. 정화는 평온 준비 생성본을 1.1배 빠르게 편집했다.
따라서 18개 파일이 모두 별개의 AI 생성 음색인 것은 아니다.

## 제작과 자동 검수

설치된 Agent Audio의 로컬 Stable Audio 3 Medium TFLite CPU audio-to-audio를 사용했다.
유료 API 호출은 0회다. Agent Audio 런타임 검증과 생성 잠금을 사용했고,
생성은 설치된 공식 CLI로 수행했다. MCP 도구에 없는 인자를 추가하지 않았다.

- 런타임 리비전: `779434a908193105335fd8d833418603625b2859`
- 모델 리비전: `da6edc54ddba10bfd79a077102ded687f80e882b`
- 모델 생성 30회, 재사용·믹스 후보 7개, 총 37개 후보를 검수했다.
- 최종 조건으로 17개 후보가 불합격, 20개가 통과했으며 용도별 18개를 선정했다.
- 불합격한 짧은 소리는 프롬프트·레퍼런스·길이를 바꿔 재생성했다.
  반복 후에도 분류가 불안정한 피드백은 통과한 생성 음색을 재사용했다.

CLAP 비교 전 입력 음량을 공통 RMS -24 dBFS로 맞췄다. 작은 피드백 음량 때문에
분류가 달라지는 문제를 줄이기 위한 비교 전처리이며, 실제 게임 믹스는 각 음량을 유지한다.
숫자 기준은 레퍼런스 유사도 ≥ 0.65, 테마 유사도 ≥ 0.35,
말소리·노래·리듬 음악·거친 잡음 점수 대비 테마 점수 여유 ≥ 0.08이다.
초기 음량 보정 전 보고서는 원본 작업 폴더에 별도로 보존했다.

20ms 에너지 기반 확장기로 낮은 코덱 잡음 바닥을 제거한다. 마지막 50ms가
효과 본체 대비 -28 dB 이하인지 페이드 전에 확인하고, 시작 8ms/끝 60ms를 다듬는다.
최종 PCM은 RMS ≥ -34 dBFS, 피크 ≤ -3.5 dBFS를 확인했다.
OGG를 다시 열어 길이·스테레오·유한한 샘플·피크 여유도 확인했다.
선정된 파일의 신호·CLAP 검수는 모두 통과했으며 **사람의 직접 청음 평가는 수행하지 않았다**.
CLAP 점수는 말소리 존재 여부나 예술적 완성도를 확정하는 판정이 아니다.

## 재현

작업 원본·레퍼런스·생성 요청·로그는 `.sfx-raw/priest-theme-20261021`에 있다.
최종 보고서에는 탈락 후보와 부모 생성 요청도 포함한다.
새 작업에는 새 폴더를 사용한다. 기존 후보 파일은 덮어쓰지 않는다.

1. 분석 Python으로 `priest-theme.py setup --work <새 폴더> --reference <기준 WAV>`를 실행한다.
2. Agent Audio Python으로 `generate-reference.py --home E:/claude/.agent-audio --manifest <폴더>/manifest.json`을 실행한다.
3. 분석 Python으로 `priest-theme.py review --work <폴더> --model <로컬 CLAP 폴더>`를 실행한다.
4. 불합격 후보의 요청을 수정하고 새 후보 번호로 다시 생성한다. 검수된 부모가 준비되면
   `priest-theme.py derive --work <폴더>`로 정화와 보조음 3종을 만들고 다시 검수한다.
5. 전 용도 통과 후 런타임 Python으로 `priest-theme.py encode --work <폴더>`를 실행한다.
   `encoded/*.ogg`와 `encoded/review.json`을 각각 게임 폴더와 검수 기록에 적용한다.

분석 환경은 `E:/claude/comfyui/.venv/Scripts/python.exe`, Agent Audio 환경은
`E:/claude/agent-audio/.venv/Scripts/python.exe`, 인코딩 환경은
`E:/claude/.agent-audio/runtime/stable-audio-3/optimized/tflite/.venv/Scripts/python.exe`다.
분석에는 numpy/scipy/torch/torchaudio/transformers와 로컬 CLAP이 필요하다.
전체 전투음 텍스트 생성기는 이 레퍼런스 파이프라인과 다르므로 사제 테마 재현에는 위 절차를 사용한다.

## 게임 연결과 검증

`src/battle/priest-sound.ts`가 실제 완료 기록을 읽어 스킬음을 고른다.
시전 실패·취소 때 완료음을 내지 않고, 정화·평온·특성의 공통 차임 중복을 막는다.
찬가는 시작에만 울리며 지속 회복과 찬가의 매 틱은 조용하다.
전이의 시전과 이동을 구분하고 공통 링크음과 겹치지 않도록 했다.
사제 피드백은 `Snd.play`에서 전용 파일로 연결하며 다른 직업의 매핑은 유지한다.
수호 영혼의 구출 이벤트는 전용 이름을 쓰고, 프로토타입 비교 모드의 차임은 보존한다.

검증 결과:

- 효과음 목록·파일·전투 연결 테스트 29개 통과.
- 스킬·전이·특성 테스트 48개 통과, 프로토타입 수치·이벤트 비교 15개 통과.
- TypeScript 검사와 Vite 배포 빌드 통과. 기존 큰 청크 경고는 남아 있다.
- 실제 브라우저에서 18/18 OGG 디코딩, 실제 엔진 이벤트 기반 18종 순차 재생 완료.
- 음소거 상태 재생·파일 검사와 음소거 해제 후 재생 확인. 테스트 화면 콘솔 오류 없음.

개발 서버에서 `/scripts/sfx/priest-audio.html`을 열면 18종을 개별·순차 테스트할 수 있다.
이 화면은 별도의 레벨 100 전투 객체로 모든 스킬을 실행하며 저장된 진행을 변경하지 않는다.
효과음 음소거는 기존 게임과 동일하게 AudioContext를 일시정지한다. 다시 켜면
남은 소리가 이어질 수 있으므로 버튼도 ‘일시정지’로 표시한다.
개발용 페이지이므로 배포 빌드에는 포함하지 않는다.
